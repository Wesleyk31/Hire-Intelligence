Recorded 19 September 2026, Australia/Perth (18 September UTC).

## Containment and repair

All six workflows were first disabled to stop repeated failing scheduled runs. Repository variable `HI_PRODUCTION_AUTOMATION_ENABLED` was set to `false`. Every production job now requires an explicit true value. The code-check workflow can be re-enabled independently; its production job remains skipped and its summary discloses the pause. Five production-only workflows remain disabled. No user-wide notification settings were changed and old failure logs were retained.

The runner now checks the actual lightweight backend before obtaining OIDC credentials or doing database work. A typed platform error preserves the provider's 402 code without exposing arbitrary response bodies. If a host outage starts during source health or QA reporting, it stops further requests immediately. Ordinary source failures still fail visibly and now print bounded source IDs and redacted reasons. The stored backfill metrics-basis enum is also recognized correctly instead of becoming NOT_VERIFIED in logs.

No application data, checkpoints, source access rules or inference gates were changed. No backend redeploy is required for these GitHub runner/workflow repairs; redeployment is currently blocked by the provider's credit limit.
