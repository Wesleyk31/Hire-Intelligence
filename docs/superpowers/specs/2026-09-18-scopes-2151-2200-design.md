## Delivery approach

**Recommended: recover and validate first.** Extend source contracts/receipts and resolve the five failed or empty source paths, then finish complete-history reconciliation and activate small canaries. This improves the usefulness and traceability of the present evidence base.

**Alternative: add sources first.** CER, WA EPA, NSW planning and national roadworks add coverage, but their access or use conditions remain external dependencies and do not solve incomplete history.

**Alternative: interface first.** Additional screens can improve navigation, but the existing 12 modules already expose the principal workflows. No broad visual redesign is proposed in this wave.

The programme spans several subsystems. Each build batch needs its own bounded implementation plan and acceptance evidence; this roadmap does not pretend to be a single implementation-ready 50-task code patch.

## First implementation batch proposed

Start with **2167–2169** (source contracts, pull receipts and explanatory health) plus **2176–2180** (the four failed feeds and one empty feed).

- Source contracts extend the existing pilot model, retaining unknown fields explicitly. They never flip registry activation or silently clear a rights/quality hold.
- Pull receipts are appended at the existing refresh/backfill boundaries. They distinguish transport, parsing, held evidence, acknowledged persistence and uncertain writes. Existing checked-intent protections remain authoritative.
- Source Admin explains why a source is unusable; a successful job or HTTP response cannot display as fresh evidence without the required date and ingestion facts.
- Recovery changes use supported provider formats/content negotiation, strict byte/time bounds and independently checked domain IDs. NT title parsers must validate their own domain rather than reuse the MODAT mine mapping. No challenged provider flow is bypassed.
- Acceptance tests cover 202, 406, empty datastore, HTML instead of data, missing IDs, old/unknown dates, duplicate pages, partial writes and retries. Existing evidence gates and account boundaries must keep passing.
- Implementation is local first. Staging and live activation remain separate acceptance steps; the old v96 app continues running until an authorised, validated release.
